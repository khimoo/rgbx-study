# 動作環境

- x86_64 アーキテクチャの WSL2
- WSL 内にインストールされた Nix（Flakes 有効化済み）
- NVIDIA GPU と、Windows 側にインストール済みの WSL 対応 NVIDIA グラフィックスドライバー

※WSL 環境内に Linux 用の NVIDIA ドライバーや CUDA Toolkit を追加でインストールする必要はありません。

# Nix の準備

`nix run` を使用するには、WSL 2 側に Nix がインストールされており、2 つの実験的機能（`nix-command` と `flakes`）が有効になっている必要があります。すでにセットアップが完了している場合は、このセクションは読み飛ばしてください。

## Nix のインストール

NixOS-WSL を使用している場合は、初期状態で Nix がインストールされているため、次の手順へ進んでください。

Ubuntu などの一般的なディストリビューションを WSL で動かしている場合は、以下の公式インストーラーを実行します。

```sh
sh <(curl -L https://nixos.org/nix/install) --daemon
```

インストール完了後、シェル（ターミナル）を再起動してください。`nix --version` を実行し、バージョン情報が表示されればインストールは成功です。

## nix-command と flakes の有効化

本リポジトリは Flakes 形式で管理されているため、これら 2 つの機能を有効にしないと、`nix run` の実行時に以下のエラーが発生して停止します。

```
error: experimental Nix feature 'nix-command' is disabled; add '--extra-experimental-features nix-command' to enable it
```

NixOS-WSL の場合は、`/etc/nixos/configuration.nix` に以下の設定を追加し、`sudo nixos-rebuild switch` を実行して反映させます。

```nix
nix.settings.experimental-features = [ "nix-command" "flakes" ];
```

それ以外の環境（Ubuntu など）では、`~/.config/nix/nix.conf` に以下の 1 行を記述します（ファイルが存在しない場合は新規に作成してください）。

```
experimental-features = nix-command flakes
```

設定後、`nix eval --expr '1+1'` を実行して `2` が返ってくれば、有効化は完了です。

# 実行方法

```sh
nix run github:khimoo/rgbx-study
```

コマンド実行後、ターミナルに表示される Gradio のローカル URL を Windows 側のブラウザで開いてください。
※初回起動時には、モデルの学習済み重み（ウェイト）が自動的にダウンロードされます。

ダウンロードされたモデルや、RGB→X デモで生成・保存された画像は、`${XDG_DATA_HOME:-$HOME/.local/share}/rgbx/rgb2x/` に保存されます。

起動時に `/usr/lib/wsl/lib` が検出された場合、CUDA ドライバーの検索パスへ自動的に追加されます。なお、NixOS における独自のドライバー配置スキームにも対応しています。

# 一括処理（バッチ処理）

Gradio の Web UI デモでは画像を 1 枚ずつしか処理できません。数千枚規模の大量の画像を一括で処理したい場合は、本リポジトリをローカルにクローンし、タスクランナーである `just` コマンドを使用して実行します。

```sh
git clone https://github.com/khimoo/rgbx-study
cd rgbx-study
nix develop -c just --list
```

`nix develop` を実行して開発用シェルに入ってから直接 `just`コマンドを実行することも可能です。

## ディレクトリ内のすべての画像を処理する

```sh
nix develop -c just batch 入力ディレクトリ 出力ディレクトリ
```

処理された画像は、元のファイル名にマップ名が追加された形式（例：`<元のファイル名>_albedo.png`）で出力ディレクトリに保存されます。標準設定ではアルベド（albedo）マップのみを生成します。その他のマップも同時に出力したい場合は、コマンドの末尾に引数として追加してください。

```sh
nix develop -c just batch 入力 出力 --aov albedo normal roughness
```

指定可能なマップは、`albedo`、`normal`、`roughness`、`metallic`、`irradiance` の計 5 種類です。

すでに出力ディレクトリにファイルが存在する画像は、自動的に処理がスキップされます。処理を途中で中断した場合でも、同じコマンドを再実行すれば、自動的に続きから処理を再開できます。

その他のオプション引数として、`--steps`（拡散モデルの推論ステップ数、デフォルト 50）、`--seed`（乱数シード）、`--max-side`（画像の長辺の上限ピクセル数、デフォルト 1000）が指定可能です。
`--seed` を省略した場合は、デモと同じく毎回ランダムな乱数で生成されます。同じ入力から同じ結果を再現したいときだけ値を指定してください。なお `--steps` と `--max-side` のデフォルト値は、どちらもデモの設定と同じです。

## 一部をサンプリング（抽出）して処理する

ファイル群が<数字.拡張子>の形の場合，とびとびに処理したりできます．
抽出方法には、ファイル名の連番に基づいてグループ化し、各グループから 1 枚を抽出する `thin` と、全体のファイル枚数を基準に一定の間隔で選出する `every` の 2 つのモードがあります．

### 1. 連番の数値でグループ化して抽出する（thin）

指定した桁数で数値を切り捨てることでファイルをグループ分けし、各グループ内で最も若い連番の画像を 1 枚ずつ抽出します。

```sh
nix develop -c just thin 入力ディレクトリ 作業ディレクトリ 6
```

例えば、ファイル名が `1234567890.123456.png` のように小数点以下が 6 桁の場合、引数に `6` を指定すると、整数部分が繰り上がるごとに 1 枚抽出されます。`7` を指定すると整数部の 1 の位まで切り捨てられるため、整数部が 10 進むごとの抽出になります。整数のみの単純な連番ファイルであれば、`2` を指定することで下 2 桁が切り捨てられ、連番が 100 進むごとに 1 枚が抽出されます。

### 2. 枚数ベースで等間隔に抽出する（every）

```sh
nix develop -c just every 入力ディレクトリ 作業ディレクトリ 25
```

この例では、画像 25 枚につき 1 枚の割合で抽出を行います。ファイル名に含まれる番号ではなく、実際のファイルの物理的な枚数をカウントするため、連番に欠番（飛び番）があっても、確実に全体から 25 分の 1 の規模に縮小できます。

### 抽出と一括処理を同時に実行する

画像の抽出（サンプリング）と一括処理（バッチ実行）を、1 つのコマンドで同時に実行することも可能です。

```sh
nix develop -c just thin-batch 入力 作業用 出力 6
nix develop -c just every-batch 入力 作業用 出力 25
```

※注意：これらのコマンドはすべて、ファイル名の末尾に連番が含まれていることを前提に動作します。連番が検出できないファイルが混ざっていると、その時点でエラーにより処理が停止します。また、作業用ディレクトリの中に（シンボリックリンクではなく）実ファイルがすでに配置されている場合も、安全のために処理が自動的に中断されます。
